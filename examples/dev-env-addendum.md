## Dev-environment repo (shared workflow)

- Sysadmin scripts, config snippets and infrastructure tooling live in **your dev-env checkout** (a git repo you own; pick the path, e.g. `~/.dev-env`).
- Scripts go under `scripts/<machine-or-context>/` in that checkout. Never leave them in ad-hoc places (`/srv/scripts/`, `~/scripts/`).
- If you write or modify a script during a session, add it to the repo, commit, and push before closing out.
- Which GitHub account/remote pushes the repo is machine-specific: see `machines/<hostname>.md`.

## Keeping the generated config in sync

- `~/.claude/CLAUDE.md` is regenerated by a scheduled job (a wrapper that calls `deploy.sh` with your `--import` / `--machines-dir` flags), not by anything tracked in git.
- Moving, renaming or replacing the deploy/sync scripts does NOT update any machine's scheduler.
- The scheduler differs per OS: cron on most Linux, a systemd user timer on Arch-based setups, a LaunchAgent on macOS (cron skips runs missed while the Mac sleeps).
- When deploy/sync script paths change, update every machine's scheduler by hand, then check it (`crontab -l`, `systemctl --user list-timers`, `launchctl list`).
- A stale entry fails silently: the machine keeps an old config and drops the addendum or overlay.

## zsh PATH: .zprofile vs .zshenv (bites SSH-exec'd commands)

- `.zprofile` only loads for **login** shells. A tool that SSHs in and runs a command directly
  (`mosh` -> `mosh-server`, `ssh host 'cmd'`) gets a **non-interactive, non-login** shell, which skips it.
- If Homebrew's `eval "$(brew shellenv)"` (or any PATH setup) lives only in `.zprofile`, those
  commands fail with `command not found` even though the binary is installed.
- Fix: put PATH-setting `eval`/`export` lines in `~/.zshenv` (sourced by *every* zsh invocation),
  instead of, or in addition to, `.zprofile`.
- Check `.zprofile`/`.zshenv` on any machine that "works interactively, fails over SSH-exec".

## Git author identity (GitHub noreply only)

GitHub blocks command-line pushes that expose a private email. So:

- Before committing or pushing in **any** repo, the author email must be a `*@users.noreply.github.com` address. Check with `git config user.email`.
- If it is not: **stop** and tell the operator. The operator fixes the git config; you do not.
- Never edit `~/.gitconfig` or set `user.email` to work around it.
- Never rewrite history, amend or force-push to fix an already-committed wrong email. Report it instead.
- Do not set `user.name`; each machine already has it.
